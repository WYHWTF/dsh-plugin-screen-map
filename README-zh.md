# dsh-plugin-screen-map 🗺️

把 `screen_read` 的冗长 UI 树压成紧凑「屏幕地图」——**保留 element id 和坐标**，所以照样能按 id 点。

## 为什么会省

一次读屏的输出常常 200~400 行，其中大部分是没有任何文字的布局壳层：

```
[e8] View {scroll} @360,691
  [e10] View {click} @360,286
    [e11] TextView "正在运行命令" @386,280
```

压掉壳层之后只剩「有字 / 可输入 / 可点的叶子」：

```
  [e11] "正在运行命令" @386,280
```

实测本机一次真实读屏压掉 22 行壳层；测试样本 682 → 507 字符（26%）。

## 规则

- **留**：有文字或 `desc` 的元素、输入类（`edit`/`wheel`/`focused`/`checked`）、可交互的叶子
- **压掉**：无文字、无描述、不可交互的容器；`scroll` 标记
- **不动**：头行、分段说明（`-- system UI --` 等）、OCR 文本行（`[t1] …`）

## 超长时怎么截断（0.1.1 起）

旧版是「从尾巴砍」，而手机界面上**输入框、发送键、权限按钮都在底部**——砍尾巴等于把最需要点的
东西砍掉。现在改成**保头 + 保尾 + 中间省略**：

```
[e0] "…" @10,0
…（中间省略 191 行；底部 input/发送键已保留尾 3 行，需要中间部分请调高 maxLines 或整屏滚动后重读）
[e199] "…" @10,199
```

省略处会写明缺了多少行，模型知道该滚动或重新读一次，而不是以为屏幕就长这样。

## 实现方式

用 `tools/post-execute` 替换**模型看到的内容**，`value` 不动（程序化访问不受影响）；解析失败或压缩后更长就原样放行。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `maxLines` | `60` | 输出总行数上限（含头、尾、省略行） |
| `headRatio` | `0.6` | 超预算时头部占比（其余给尾部；手机界面建议别低于 0.5） |

MIT，无依赖，`node test/unit.mjs` 可跑。

## 30 秒自检（手机上）

1. 让模型看一眼屏幕（例如「现在屏幕上有什么？」）
2. 输出末尾应当出现「（已压掉 N 行布局壳层）」，超过预算时还有「…（中间省略 N 行…）」
3. 没有这些字样 → 查 profile 的 `dsh.profile.bundles` 里有没有 `dsh-plugin-screen-map`

注意：它省的是 **token**，不是时间——读屏本身还是慢（本机实测一次约 30 秒）。
